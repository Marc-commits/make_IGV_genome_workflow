# Snakemake workflow audit — 2026-09-19

Audit of this repo (a single-rule Snakemake module wrapping a vendored
`make_igv_genome.sh` bash script into an IGV `.genome` archive builder)
against the `snakemake-audit-workflow` skill's checklist. This is a small,
focused module (not a multi-rule pipeline), so most checklist items that
assume a bigger repo (CODE_OF_CONDUCT.md, config schema, per-scenario test
configs, module cherry-picking, sentinel files) are correctly absent/not
applicable rather than failures.

## Findings

### Structural checklist — PASS, minor notes

- `Snakefile` (top-level, not `workflow/Snakefile`) — acceptable for a module
  meant to be included via `module:` from consumers.
- `config/config.yaml` present with a header comment but no per-key inline docs;
  no `config/README.md`, no `config/example.config.yaml`, no schema — reasonable
  given only 5 flat keys, but worth a one-line TODO for future-proofing.
- `workflow/rules/igv_genome.smk`, `workflow/envs/igv_genome.yaml` +
  `igv_genome.linux-64.pin.txt` (pin file mtimes match the env yaml — not stale),
  `workflow/scripts/make_igv_genome.sh` + its `_README.md`, `workflow/rulegraph.svg`
  all present and current.
- Two parallel test suites: `.tests/unit/` (pytest, Snakemake rule-level
  integration test with `common.py`/`cmp_cmds`) and top-level `tests/` (bats,
  ported unchanged from the upstream script's own suite, tests the vendored
  script directly). This is intentional layering, not redundant — no finding.
- No `LICENSE`/`CODE_OF_CONDUCT.md`/`CONTRIBUTING.md`/catalog file — fine for an
  internal submodule, not flagged as a defect.

### Conda env pinning — PASS

`workflow/envs/igv_genome.linux-64.pin.txt` exists and is in sync with
`igv_genome.yaml`.

### Wrapper-replacement — no action

Script only shells out to `samtools faidx`, `zip`/`unzip`, and a local
`python3` validation snippet — no snakemake-wrapper worth adopting for this.

### Rule-authoring hygiene — PASS, one formatting nit

`workflow/rules/igv_genome.smk:1-26` — no lambdas, no absolute paths, correct
use of `workflow.source_path()` (with a comment explaining why, not
`workflow.basedir`), `log:` is declared and actually used (`&> {log}` at line 26),
`set -euo pipefail` + `die()` in the script itself. The only issue is a
**snakefmt ordering violation**, confirmed by running `snakefmt --check --diff`:

- `workflow/rules/igv_genome.smk`: `log:`/`benchmark:`/`conda:` (lines 15-20)
  should come before `params:` (lines 7-14).
- `Snakefile`: `default_target: True` (line 11) should come before the rule's
  docstring (line 8), inside `make_igv_genome_workflow_all`.

Both are pure block-reordering, no logic change. Recorded as a TODO; not
applied automatically.

### Module/submodule usage, sentinel files — PASS / N/A

No `module:`/`use rule` in this repo (it's the thing consumed, not a consumer),
and no sentinel/marker-file outputs — the rule's only output is the real
`.genome` archive.

### Lint/format tooling

- `snakemake --lint`: passes ("Congratulations, your workflow is in a good
  condition!").
- `snakefmt --check`: fails (2 files, see above) — this is the one concrete
  actionable finding.

### Config documentation — PARTIAL

`config/config.yaml` has a 3-line header comment but no per-key inline comments,
and there's no `config/example.config.yaml`. Low priority given only 5 flat
scalar keys, all named self-explanatorily and already documented in the README's
"Edit `config/config.yaml` (`fasta`, `genefile`, `genome_id`, `genome_name`,
`output`)" line.

### Documentation — PASS, one nice-to-have

`README.md` describes the module, standalone usage, module-consumption pattern
(with the modern `module: config:` syntax), and both test suites. It does not
embed `workflow/rulegraph.svg` inline — minor, optional.

`CHANGELOG.md`/`TODO.md` are current and already track the one known real
issue: the vendored script's `--tldr` flag divergence from upstream commit
`8c2a815` (`TODO.md`), which is out of scope for this audit (already tracked).

`workflow/scripts/make_igv_genome_README.md` is a thorough, up-to-date
bioinformatic audit of the script's data transformations (fasta indexing,
`property.txt` generation, zip packaging/verification) — matches the current
`make_igv_genome.sh` content, no re-assessment needed.
